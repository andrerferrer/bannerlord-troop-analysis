# Multi-track canonical identity audit — 2026-07-23 batch

## Decision

The 2026-07-23 result screens are a **mixed-track dataset**. They contain Realm of Thrones troops, official War Sails troops, and Rhodok-labelled troops whose exact source track is not yet proven. The dataset must not be canonicalized against the vanilla + War Sails audit alone.

## Conservative matching policy

A canonical ID is accepted only when a versioned repository artifact or generated track audit contains an exact normalized `name → troop_id` relationship. Similar slugs, apparent naming conventions, likely XML IDs, and fuzzy matches are not enough.

Status values include:

- `confirmed_id`: a unique exact normalized name-to-ID match or a preserved verified manual confirmation;
- `track_confirmed_id_unresolved`: track is proven, but the reference does not expose an ID;
- `ambiguous_exact_name`: the same normalized name maps to multiple track/ID candidates;
- `conflict_existing_vs_track_audit`: a supplied track audit contradicts an existing confirmed ID;
- `unresolved`: track or ID is not proven;
- `missing_audit_row`: baseline label was not represented in the audit table.

## Automated resolution

The repository now includes:

```text
scripts/analysis/build_canonical_identity_audit.py
scripts/run_canonical_identity_pipeline.ps1
```

The resolver consumes the `<track>_troops.csv` outputs generated by `scripts/normalization/rebuild_vanilla_audit.py`. Matching is deliberately limited to exact normalized display names. It normalizes Unicode punctuation, whitespace, and result-table tier suffixes, but does not use fuzzy matching or treat a provisional slug as an XML ID.

Example:

```powershell
.\scripts\run_canonical_identity_pipeline.ps1 `
  -TrackAudits @(
    "vanilla=data\vanilla\audit\vanilla_troops.csv",
    "realm_of_thrones=data\realm_of_thrones\audit\realm_of_thrones_troops.csv",
    "rhodok_mod=data\rhodok_mod\audit\rhodok_mod_troops.csv"
  )
```

To enforce the canonical join gate:

```powershell
.\scripts\run_canonical_identity_pipeline.ps1 `
  -TrackAudits @(
    "vanilla=data\vanilla\audit\vanilla_troops.csv",
    "realm_of_thrones=data\realm_of_thrones\audit\realm_of_thrones_troops.csv",
    "rhodok_mod=data\rhodok_mod\audit\rhodok_mod_troops.csv"
  ) `
  -RequireComplete
```

`-RequireComplete` fails while any label is unresolved, ambiguous, or conflicting. Existing confirmed decisions are preserved when no new candidate exists and are blocked rather than overwritten when a supplied audit contradicts them.

## Important blocker

vanilla/War Sails and Realm of Thrones. It reported 1,937 and 6,187 rows
respectively, plus their SHA-256 hashes. Its attempted Base64 payload transport
lost bytes inside a single XZ block, so the complete audit files cannot be
validated or materialized from the Git history.

The 17 exact relationships explicitly published in that PR are now versioned and
reproducible through the normal resolver. The remaining seven labels are:

- five Rhodok-labelled troops whose producing module is no longer identified;
- `Rhoynar Bahriyyah [T5]`, whose only recorded near miss changes the culture;
- `Reaver [T4]`, whose only recorded near miss changes both the full name and tier.

No near miss is promoted. `canonical_identity_resolution_report.json` records the
17/24 result, and `--require-complete` continues to exit non-zero. Attribute and
equipment joins remain blocked because the compact recovery tables do not contain
the all-troop audit features.
