# Phase 0 baseline audit — combat screenshots 2026-07-23

## Status

This is a **first analytical pass**, not a final troop ranking. It uses the locally verified normalized archive whose SHA-256 is:

```text
10446ce7afb01ec35211c06468812bf2fa3d53e6091f128a7ec67ca605dea2aa
```

The purpose is to identify the minimum defensible analysis population, expose data-quality blockers, and establish a reproducible baseline before troop-attribute modeling.

## Main methodological correction

The first-pass aggregate files mix rows from the player side and the opposing side. Because the captured result screens are victories, combining both sides creates a strong outcome bias: player-side troops are sampled from the winning side while enemy troops are sampled from the losing side.

All primary campaign-performance rankings must therefore be split by relationship to the player. The baseline in this report uses only rows where:

```text
side == player_side
```

Enemy-side rows remain useful for matchup and defeat-side analyses, but should not be pooled into the same ranking.

### Strict baseline population

The strict profile applies all of the following:

- troop row included in the first-pass primary dataset;
- player side only;
- known context: `field`, `siege_attack`, or `siege_defense`;
- `needs_review == false`;
- all core numeric fields present;
- `deployed > 0`;
- suspected siege-engine-assisted occurrence excluded;
- repeated occurrences consolidated at battle × troop × context before aggregation.

## Baseline definition

For each troop and context:

```text
kills_per_deployed = sum(kills) / sum(deployed)
casualty_rate = sum(deaths + wounded) / sum(deployed)
death_rate = sum(deaths) / sum(deployed)
```

Confidence intervals are generated by resampling **battle-level troop rows**, not individual soldiers or raw screenshot rows. This preserves the battle as the independent sampling unit and avoids artificial precision.

### Field observations

The leading point estimates are Reach Flower Knight, Baratheon Hammerknight, Celtigar Banneret, Stormlands Heavy Crossbowman, Queen's Man, Rhoynar Bahriyyah, Water Gardens Sentinel, and Dragonstone Elite Halberdier.

Several intervals are very wide. For example, Reach Flower Knight has 28 deployed over 6 field battles and an interval of roughly 1.87–8.21 kills/deployed. It should not be treated as conclusively superior to the larger-sample alternatives.

### Siege attack

Only seven troop labels meet the minimum threshold. Rhoynar Bahriyyah leads the point estimate at 2.951 kills/deployed over 41 deployed and 3 battles, followed by Elite Hired Crossbow at 2.048. The sample is too small for a stable general siege ranking.

## What this pass established

1. **Player side and enemy side must be separated.** This is now a required analytical dimension.
2. **The current first-pass ranking is not yet authoritative.** More than half of primary occurrences are marked for review.
3. **Troop identity normalization is a major blocker.** OCR variants split the same probable troop across multiple slugs, including `stormlands_heavy_crossbowmant5` and `stormlands_heavy_crossbowman_t5`.
4. **Strict filtering changes the usable dataset materially.** Only 406 of 1,213 primary occurrences enter the strict player-side baseline.
5. **Uncertainty is large for many apparent leaders.** Point estimates alone overstate ranking confidence.
6. **Siege defense cannot currently be ranked.** The strict sample has only 13 occurrences and no troop meets the eligibility gate.
7. **Campaign observations measure realized contribution, not isolated causal strength.** Army composition, commands, enemy composition, battle duration, perks, terrain, and result remain confounders.

## Gate decision

**Phase 0 is partially passed.** The archive is structurally valid and a defensible strict baseline can be produced. The dataset is not yet canonical because identity aliases and the P0 review queue remain unresolved.

The project may proceed with descriptive exploratory reporting, but should not yet:

- recalibrate the frozen troop score model;
- infer causal attribute weights;
- publish a universal troop tier list;
- train a battle simulator.
